## Схемы для чата и MCP

`llm/workflows/openwebui_flux3_t2i.json` и `openwebui_flux3_edit.json` (формат API ComfyUI):

```
UNETLoader → ModelSamplingFlux → KSampler → VAEDecode → SimpleGenFreeVRAM → SaveImage
CLIPLoader(qwen3vl, flux3) → CLIPTextEncode(SimpleGenUnloadLLM(prompt)) / CLIPTextEncode("")
правка: LoadImage → ImageScaleToTotalPixels(1 Мп) → GetImageSize → EmptyFlux2LatentImage
        ReferenceMultiLatent(resolution=resize, resolution.megapixels=1.0, images.image0..N)
```

Схемы проверены в ComfyUI без запуска: одно поле нарочно испорчено (`weight_dtype`), и ComfyUI сообщил только об этой ошибке.

## Инструмент для чата `flux_studio` (`llm/tools/flux_studio.py`)

- `create_image(prompt, size, quality, seed)` — новая картинка. Gemma сама выбирает размер под сюжет: 832×1216 портрет, 1216×832 пейзаж, 1344×768 баннер, 1024×1024 квадрат.
- `edit_image(prompt, images, quality, seed)` — правка последней картинки беседы (вашей или нарисованной) или объединение до 4 картинок. Картинки берутся из базы чата, где есть и сгенерированные, а для временного чата — из сообщений.
- Картинка появляется в чате так же, как у встроенного генератора (`chat:message:files`). В статусе видны размер, режим и seed.
- **Самопроверка:** инструмент возвращает словарь с уменьшенной копией (JPEG 768 px, data-URL), Open WebUI показывает её модели. Gemma сверяет результат с запросом и прямо говорит, если что-то не так. С зрением на CPU это +~12 с на картинку.

## Режимы: подпись или задание (flux_studio v0.2)

Сравнение на обложке книги «Развод. Всё записано на маму» (библия серии приложена файлом, эталон — обложка ChatGPT):

| Цепочка | Итог |
|---|---|
| Gemma пишет подпись → FLUX | красивый натюрморт с хлебом, но без героини; рамки Gemma не передала |
| запрос → улучшатель BFL → FLUX | перегружено, случайный «исторический роман» |
| запрос + логлайн → BFL → FLUX | приемлемо, но много деталей |
| **Gemma пишет короткое задание → BFL → FLUX** | **лучшее из наших**: одна героиня, чистая композиция, место под название |

ChatGPT (GPT Image 2.5, Эло 1222 против 1043) всё равно заметно лучше. FLUX 3 пишет кириллицу: крупно почти без ошибок, мелкий текст с опечатками («занисано»).

Поэтому у `create_image` и `edit_image` два режима:
- **`brief`** — Gemma как арт-директор пишет короткое задание, официальный улучшатель BFL (Qwen3.5-9B, узел `TextGenerate` внутри схемы ComfyUI, параметры как в схемах BFL) превращает его в подпись для FLUX. Для правок улучшатель видит картинку. Подпись возвращается модели (`caption`). Первый запуск на 1–4 минуты дольше (загрузка 9,8 GB), дальше ~10 с на картинку. Улучшатель детерминирован: разные варианты даёт только seed FLUX.
- **`prompt`** — Gemma пишет подпись сама; для простых картинок, быстрее.

Инструмент сам ходит в ComfyUI (`/prompt`, `/history`, `/view`), чтобы забрать и картинку, и подпись улучшателя.

## Навык image-generation

Все правила картинок вынесены из системного промпта в навык Open WebUI (`prompts/skills/image-generation.md`, загружает `owui_setup.py`). Модель видит только название и описание навыка и читает его целиком через `view_skill` перед первой генерацией. Системный промпт сократился с ~8,9 до ~5,6 тыс. символов.

В навыке: когда рисовать, выбор режима, композиция до описания, как писать задание и подпись, **масштаб и пропорции** всех предметов и людей (урок «кольца размером с браслет»), люди и руки, один и тот же персонаж в серии, цвета (в том числе hex), замены негативного запроса, текст, жанровые условности обложек, правки, самопроверка, «одна правка за раз». Часть правил — из официальных навыков BFL ([black-forest-labs/skills](https://github.com/black-forest-labs/skills)): свет важнее всего, порядок слов, hex-цвета, точный текст и логотипы — на программное наложение.

2026-10-25 навык переписан короче и явнее (14,6 → 7,9 тыс. символов): вверху 6 обязательных шагов (рисовать, а не описывать; правка вместо перерисовки; режим; композиция; запись; проверка превью), правила подписи списком, стили по одной строке, отдельные разделы обложек, размеров, правок и проверки. Причина — опыт с навыком поиска: Gemma 26B-A4B лучше держит короткий жёсткий список, чем длинные пояснения. Запись «Памяти» о любимом стиле картинок удалена по просьбе пользователя.

Отложено: накладывать текст обложки программно настоящим шрифтом (FLUX рисует без текста с пустой зоной).

## Автовключение навыка (фильтр image_skill_auto)

Gemma навык сама не читает, а сразу рисует (и тогда, например, берёт размер 1024x1024 вместо 832x1216 для обложки). Поэтому `llm/functions/image_skill_auto.py` — фильтр Open WebUI (`inlet`, привязан к модели через `meta.filterIds`): если в сообщении просят картинку (глагол рисования, или действие + визуальная вещь: «придумай обложку», «сделай логотип», приложенная картинка + «убери/измени», правка в беседе, где уже рисовали), он кладёт в запрос `skill_ids = ["image-generation"]`, и Open WebUI вставляет навык целиком именно в это сообщение. В остальных беседах навык не тратит контекст. Проверено: с «сделай обложку» модель цитирует правило размера из навыка, без триггера — навыка нет.

Ещё из живого чата: Gemma поняла «придумай обложку» как «предложи идеи» (думает по-английски: think up) и не рисовала; приложенный файл доходил до модели тремя кусками по 1000 символов. Исправлено правилом в первом шаге плана размышлений и `RAG_FULL_CONTEXT=true`. Логическая ошибка «пишет на закрытой книге» — в навыке правило о физически возможных действиях с предметами.

## Ограничения FLUX 3 (на 24.10.2026)

- **LoRA мало:** ~26 на Hugging Face, в основном экспериментальные (Outpaint, Restore, Consistency, Angles, photo-aesthetics, 4-step для базовой). Старые LoRA Z-Image не подходят.
- **ControlNet нет.** Его заменяют картинки-образцы (до 10), рамки на сетке 0–1000 и правка. По словам BFL, образцы «задают содержание, но не фиксируют структуру», так что набросок — это «по мотивам», не контур в контур.
- Модель обучали на отфильтрованных данных, она строже Z-Image.
