# Промпты

Файлы лежат в `prompts/`:
- `system_prompt_en.txt` — общий системный промпт;
- `thinking_plan_en.txt` — порядок размышлений, добавляется только к основной модели;
- `official/` — официальные промпты-улучшатели BFL (FLUX 3), Lightricks (LTX), Wan и Z-Image;
- `gemma4_assistant_ru.md` — первая русская версия, оставлена для истории.

## Почему промпт на английском, а ответ на русском

Английский текст на ~30% короче по токенам, а размышления на английском у Gemma стабильнее. В промпте: «думай по-английски, финальный ответ только по-русски, если не просят другой язык». Последняя оговорка важна: тестовая версия без неё проваливала просьбу «ответь на каннада».

## Разделы системного промпта

| Раздел | Что делает | Откуда взялось |
|---|---|---|
| `<|think|>` + дата `{{CURRENT_DATE}}` | включает размышления; модель знает «сегодня» | документация Gemma 4 |
| Language | язык мыслей и ответа | см. выше |
| Reading the request | опечатки, неправильная раскладка («ghbdtn»), голосовой ввод; при важной двусмысленности — один вопрос; на ложную посылку — сказать | просьба пользователя |
| Style | без эмодзи, сначала ответ | просьба пользователя |
| Honesty | не выдумывать факты, версии, ссылки | — |
| Counting and arithmetic | точные подсчёты и вычисления — только через `execute_code` | тест-ловушка: ошибка в подсчёте букв |
| Web search | ссылка на источник у каждого утверждения из поиска, иначе пометка «по моим данным, не проверено»; первоисточники; проверка дат; **никогда не изображать поиск** | исследование StrictCitations (MDPI); Gemma без поиска писала «основываясь на анализе рецептов» |
| Long conversations | после сжатия искать точные детали через `search_current_chat`; другие беседы — `search_chats`; память — `add_memory` | — |
| Images | когда рисовать, как писать подпись для FLUX 3, когда править, а не рисовать заново | официальные промпты улучшателя BFL |
| User's machine | Windows 11, PowerShell, uv; предупреждать перед опасными командами | — |

## План размышлений (thinking_plan_en.txt)

1. **Цель:** сначала расшифровать сообщение (опечатки, раскладка), потом одной строкой — что нужно на самом деле.
2. **План:** 3–7 конкретных шагов.
3. **Разбор по шагам:** если есть результаты поиска, начинать с них, а память использовать только для пробелов. Пошаговый «экспертный» разбор без этого правила уводил модель в собственную память даже при свежих результатах.
4. **Проверка** — выбрана тестом-ловушкой (см. [09-benchmarks.md](09-benchmarks.md)):
   - попробовать опровергнуть свой черновик;
   - пересчитать числа, перечитать вопрос в поисках ложной посылки и пропущенной детали;
   - **проверять инструментом, а не по памяти**: код для чисел, подсчётов и дат; поиск или беседа для фактов;
   - каждую проверку делать один раз;
   - менять ответ только при конкретной ошибке;
   - следовать пометкам посредника `[Pause]` / `[Thinking time is up]`.
5. **Ответ** по-русски, план не показывать.

Вариант с «рассмотри самую сильную альтернативу» на тесте зацикливал модель (кувшины: 2 из 2 попыток до предела), поэтому убран. Пользователь предсказал это заранее.

## Правила подписи для FLUX 3

Взяты из официальных промптов улучшателя BFL (`prompts/official/flux3_upsampler_*.txt`). В карточке модели прямо сказано: без улучшателя запросов модель не использовать, а улучшателем может быть любая LLM с правильной инструкцией. Здесь эту роль выполняет Gemma.

- Один абзац прозы на 100–350 слов, без тегов.
- Сначала тип кадра и стиль («Full-color outdoor photograph, …»), потом сцена, свет и камера, потом каждый объект с цветом, материалом и состоянием.
- Расположение словами (on the left, in the foreground).
- Настроение — через видимое; чего не должно быть — как то, что есть («a bare white wall»).
- Стиль описывать признаками, а не названием картины.
- Текст на картинке — в кавычках, со шрифтом, цветом и местом.
- Правка: повелительная инструкция на 50–150 слов, только изменение и его последствия (тени, отражения, чем заполнить убранное), в конце — что остаётся без изменений.

Расширенное правило «что значит нарисовать»: «придумай обложку / постер / логотип / аватарку / баннер» — это тоже просьба о картинке. Текстом отвечать, только если явно просят идеи или описание.

## Навык web-research и фильтр research_skill_auto

Разбор беседы «новости эмуляции за неделю» (2026-10-25): Gemma считала дату в промпте «симуляцией» («2026 — это будущее, на самом деле 2024»), искала «October 2024», представляла результаты в мыслях вместо поиска, писала общие запросы («latest news» — в выдаче NDTV и «папка Recent в Windows»), не открыла ни одной страницы через `fetch_url`, запланировала ещё один поиск и не сделала его, ответила общими фразами без дат и ссылок.

Исправления:
- **Системный промпт:** дата настоящая, а не смоделированная; `search_web` ищет в сегодняшнем интернете, где есть страницы этого года; не предсказывать выдачу; в запросах о свежем — месяц и год плюс конкретные имена; запланированный поиск или `fetch_url` делать до ответа; день недели `{{CURRENT_WEEKDAY}}` рядом с датой (Gemma путала субботу и воскресенье, а от этого зависит «эта неделя»). Точное время в промпт не добавлено: начало промпта менялось бы каждую минуту, и llama.cpp пересчитывал бы весь контекст беседы.
- **Навык `prompts/skills/web-research.md`** — порядок поиска: уточнить вопрос и перевести «эту неделю» в даты; спланировать 2–4 конкретных запроса (имена, месяц и год, тип страницы: release notes, roundup, changelog); оценивать выдачу и переформулировать, а не повторять; для новостей за период обязательно открыть хотя бы одну страницу; проверить даты каждого пункта («добавлено в список» ≠ «вышло»), качество источника, расхождения; самопроверка перед ответом; ответ — факты с версией, датой и ссылкой. Без списков «любимых сайтов»: навык учит находить источники на любую тему (сначала хаб темы — обзоры, трекеры, awesome-списки; для фактов — официальные сайты и GitHub releases; для незнакомой темы — обзор, чтобы узнать имена проектов; заблокированные страницы не повторять). Сайтов под частые темы пользователя нарочно нет: это натаскивание на тест, а не умение искать.
- **Фильтр `llm/functions/research_skill_auto.py`:** при включённом «Веб-поиске» добавляет навык в сообщения, где просят найти что-то («найди», «погугли», «в интернете») или спрашивают свежее (новости, релизы, версии, цены, «за неделю», latest, release notes). Проверен на 10 примерах; без кнопки поиска не срабатывает.

Проверка через API: встроенные `search_web`/`fetch_url` Open WebUI даёт только запросам с `session_id` (как из браузера), а цикл инструментов идёт в фоне — API возвращает лишь первый шаг. После правок Gemma сразу ищет «emulation news October 2026» и «PC game porting news October 2026» вместо 2024; полный ответ проверяется в чате.
