# Промпты

Файлы лежат в `prompts/`:
- `system_prompt_en.txt` — общий системный промпт;
- `thinking_plan_en.txt` — порядок размышлений, добавляется только к основной модели;
- `official/` — официальные промпты-улучшатели BFL (FLUX 3), Lightricks (LTX), Wan и Z-Image;
- `gemma4_assistant_ru.md` — первая русская версия, оставлена для истории.

## Почему промпт на английском, а ответ на русском

Английский текст на ~30% короче по токенам, а размышления на английском у Gemma стабильнее. В промпте: «думай по-английски, финальный ответ только по-русски, если не просят другой язык». Последняя оговорка важна: тестовая версия без неё проваливала просьбу «ответь на каннада».

## Разделы системного промпта

| Раздел | Что делает | Откуда взялось |
|---|---|---|
| `<|think|>` + дата `{{CURRENT_DATE}}` | включает размышления; модель знает «сегодня» | документация Gemma 4 |
| Language | язык мыслей и ответа | см. выше |
| Reading the request | опечатки, неправильная раскладка («ghbdtn»), голосовой ввод; при важной двусмысленности — один вопрос; на ложную посылку — сказать | просьба пользователя |
| Style | без эмодзи, сначала ответ | просьба пользователя |
| Honesty | не выдумывать факты, версии, ссылки | — |
| Counting and arithmetic | точные подсчёты и вычисления — только через `execute_code` | тест-ловушка: ошибка в подсчёте букв |
| Web search | ссылка на источник у каждого утверждения из поиска, иначе пометка «по моим данным, не проверено»; первоисточники; проверка дат; **никогда не изображать поиск** | исследование StrictCitations (MDPI); Gemma без поиска писала «основываясь на анализе рецептов» |
| Long conversations | после сжатия искать точные детали через `search_current_chat`; другие беседы — `search_chats`; память — `add_memory` | — |
| Images | когда рисовать, как писать подпись для FLUX 3, когда править, а не рисовать заново | официальные промпты улучшателя BFL |
| User's machine | Windows 11, PowerShell, uv; предупреждать перед опасными командами | — |

## План размышлений (thinking_plan_en.txt)

1. **Цель:** сначала расшифровать сообщение (опечатки, раскладка), потом одной строкой — что нужно на самом деле.
2. **План:** 3–7 конкретных шагов.
3. **Разбор по шагам:** если есть результаты поиска, начинать с них, а память использовать только для пробелов. Пошаговый «экспертный» разбор без этого правила уводил модель в собственную память даже при свежих результатах.
4. **Проверка** — выбрана тестом-ловушкой (см. [09-benchmarks.md](09-benchmarks.md)):
   - попробовать опровергнуть свой черновик;
   - пересчитать числа, перечитать вопрос в поисках ложной посылки и пропущенной детали;
   - **проверять инструментом, а не по памяти**: код для чисел, подсчётов и дат; поиск или беседа для фактов;
   - каждую проверку делать один раз;
   - менять ответ только при конкретной ошибке;
   - следовать пометкам посредника `[Pause]` / `[Thinking time is up]`.
5. **Ответ** по-русски, план не показывать.

Вариант с «рассмотри самую сильную альтернативу» на тесте зацикливал модель (кувшины: 2 из 2 попыток до предела), поэтому убран. Пользователь предсказал это заранее.

## Правила подписи для FLUX 3

Взяты из официальных промптов улучшателя BFL (`prompts/official/flux3_upsampler_*.txt`). В карточке модели прямо сказано: без улучшателя запросов модель не использовать, а улучшателем может быть любая LLM с правильной инструкцией. Здесь эту роль выполняет Gemma.

- Один абзац прозы на 100–350 слов, без тегов.
- Сначала тип кадра и стиль («Full-color outdoor photograph, …»), потом сцена, свет и камера, потом каждый объект с цветом, материалом и состоянием.
- Расположение словами (on the left, in the foreground).
- Настроение — через видимое; чего не должно быть — как то, что есть («a bare white wall»).
- Стиль описывать признаками, а не названием картины.
- Текст на картинке — в кавычках, со шрифтом, цветом и местом.
- Правка: повелительная инструкция на 50–150 слов, только изменение и его последствия (тени, отражения, чем заполнить убранное), в конце — что остаётся без изменений.

Расширенное правило «что значит нарисовать»: «придумай обложку / постер / логотип / аватарку / баннер» — это тоже просьба о картинке. Текстом отвечать, только если явно просят идеи или описание.

## Навык web-research и фильтр research_skill_auto

Разбор беседы «новости эмуляции за неделю» (2026-10-25): Gemma считала дату в промпте «симуляцией» («2026 — это будущее, на самом деле 2024»), искала «October 2024», представляла результаты в мыслях вместо поиска, писала общие запросы («latest news» — в выдаче NDTV и «папка Recent в Windows»), не открыла ни одной страницы через `fetch_url`, запланировала ещё один поиск и не сделала его, ответила общими фразами без дат и ссылок.

Исправления:
- **Системный промпт:** дата настоящая, а не смоделированная; `search_web` ищет в сегодняшнем интернете, где есть страницы этого года; не предсказывать выдачу; в запросах о свежем — месяц и год плюс конкретные имена; запланированный поиск или `fetch_url` делать до ответа; день недели `{{CURRENT_WEEKDAY}}` рядом с датой (Gemma путала субботу и воскресенье, а от этого зависит «эта неделя»). Точное время в промпт не добавлено: начало промпта менялось бы каждую минуту, и llama.cpp пересчитывал бы весь контекст беседы.
- **Навык `prompts/skills/web-research.md`** — порядок поиска: уточнить вопрос и перевести «эту неделю» в даты; спланировать 2–4 конкретных запроса (имена, месяц и год, тип страницы: release notes, roundup, changelog); оценивать выдачу и переформулировать, а не повторять; для новостей за период обязательно открыть хотя бы одну страницу; проверить даты каждого пункта («добавлено в список» ≠ «вышло»), качество источника, расхождения; самопроверка перед ответом; ответ — факты с версией, датой и ссылкой. Без списков «любимых сайтов»: навык учит находить источники на любую тему (сначала хаб темы — обзоры, трекеры, awesome-списки; для фактов — официальные сайты и GitHub releases; для незнакомой темы — обзор, чтобы узнать имена проектов; заблокированные страницы не повторять). Сайтов под частые темы пользователя нарочно нет: это натаскивание на тест, а не умение искать.
- **Фильтр `llm/functions/research_skill_auto.py`:** при включённом «Веб-поиске» добавляет навык в сообщения, где просят найти что-то («найди», «погугли», «в интернете») или спрашивают свежее (новости, релизы, версии, цены, «за неделю», latest, release notes). Проверен на 10 примерах; без кнопки поиска не срабатывает.

Проверка через API: встроенные `search_web`/`fetch_url` Open WebUI даёт только запросам с `session_id` (как из браузера), а цикл инструментов идёт в фоне — API возвращает лишь первый шаг. После правок Gemma сразу ищет «emulation news October 2026» и «PC game porting news October 2026» вместо 2024; полный ответ проверяется в чате.

### Вторая итерация: поиск читает инструмент, а не модель

Длинный навык с чек-листом не помог: Gemma выписывала два первых шага, делала один заход поиска и отвечала по сниппетам (`fetch_url` не вызвала ни разу), ответ стал хуже. Это предел модели: небольшие модели плохо делают цепочки «результат → следующий запрос» (в обзорах так умеют модели от ~70B), а Gemma 4 чаще Qwen отвечает по памяти. Что сделано по практикам поисковых агентов (Anthropic: «start wide, then narrow», бюджет вызовов, правило остановки, первоисточники; практики: «ищи до ответа», «после N страниц отвечай», нумерованные ссылки; явный диапазон дат вместо «недавно»):
- **`llm/tools/web_research.py`** — свой `search_web`: функция с тем же именем занимает место встроенного (Open WebUI добавляет встроенный, только если имени ещё нет), встроенный `fetch_url` остаётся. Ищет через SearXNG с `time_range` (day/week/month/year; если за период меньше 3 результатов — добавляет результаты без фильтра с пометкой) и сразу читает до 3 лучших страниц загрузчиком Open WebUI (по 4000 символов, видео и соцсети пропускает), даты — из SearXNG или первая дата на странице. Одного вызова хватает даже Gemma. Если модель не передала `period`, берёт его из подсказки фильтра в последнем сообщении (`__messages__`). При выключенной кнопке «Веб-поиск» честно отказывается.
- **Фильтр `research_skill_auto` 0.2:** кроме навыка, дописывает к сообщению `[Context: today is … "this week" means 2026-10-19 to 2026-10-25. Call search_web with period="week".]` для «сегодня», «вчера», «эта/прошлая неделя», «за неделю», «этот месяц», «недавно/свежие», «этот год»; для цен окно не ставит (у страниц магазинов нет даты).
- **Навык сокращён** до 7 правил и формата ответа: искать до ответа; диапазон из подсказки; сначала 1–2 коротких широких запроса, потом сужать по найденным именам; факты из текстов страниц, а не сниппетов; 2–4 вызова, не больше 6; первоисточники; даты по самому пункту, а не «added/last checked»; ответ с нумерованными ссылками [n] и списком источников.
- **Системный промпт:** «ты (Gemma 4) вышла весной 2026, твои данные кончаются раньше — многие месяцы событий отсутствуют в памяти» (конкретная разница во времени вместо абстрактного «дата настоящая»); фильтр period вместо «пиши месяц и год»; search_web уже содержит текст страниц.

### Третья итерация: полнота и порядок

С новым инструментом ответ стал конкретным (даты, номера источников, факты из текстов страниц), но неполным: Gemma сделала один поиск «emulation and porting news», и культовая новость недели (неофициальные порты Uncharted на ПК, 19.10), крупные релизы рекомпиляций и утилиты в выдачу не попали. Раз модель делает один вызов, `search_web` 0.2 принимает 2–4 запроса через « ; » в одном вызове: выполняет их параллельно, чередует результаты (каждая часть темы в начале списка), читает до 4 страниц по 3500 символов. Навык: широкую тему сначала разбить на части (релизы программ, игры или продукты, утилиты, железо) — по запросу на часть в одном вызове; порядок по значимости (известные тайтлы и франшизы, 1.0 и мажорные версии, то, о чём пишут несколько сайтов — первыми; мелочь в конце строкой «Ещё: …»; интересы пользователя из памяти — вперёд).

### Четвёртая итерация: два прохода, смежные инструменты, технический стиль

- `search_web` считает проходы в рамках одного ответа (по `message_id`) и дописывает в конец результата: после первого — «выпиши конкретные имена из текстов и сделай второй поиск по ним и по недостающим частям темы (например, утилиты вокруг неё), ответ — после второго прохода»; после второго — «отвечай, если ничего важного не упущено»; дальше — «отвечай сейчас». Подсказка в результате инструмента работает надёжнее правила в навыке: небольшая модель её видит ровно в момент решения.
- Навык: правило 3 — два прохода (широко по частям темы, включая инструменты и утилиты вокруг неё, потом по найденным именам); бюджет 2–3 вызова, не больше 5; даты мягче — пункты за день-два до периода допустимы с датой, явно старые в конец или убрать.
- Системный промпт, раздел Style: пользователь технический (Linux, DevOps, Kubernetes, локальный ИИ, эмуляция) — по умолчанию версии и числа, что изменилось внутри (API, рендереры, форматы, архитектура), команды и конфиги; без азов и маркетинговых слов, если не спрашивают.

### Пятая итерация: смысл темы, хабы, без догадок

Два прохода заработали (во втором — имена из первого), ответ стал техничным, но по смыслу мимо: «портирование» понято бытово (Playden — Wine на взломанной PS5, это совместимость, а не порт), во второй проход Gemma вставила от себя «GTA 6 PC port» → в ответе слух о релизе, первый проход «emulation news this week» дал общие техносайты и пропустил волну рекомпиляций. Навык: в первом проходе выяснить, что слова значат для специалистов поля, и обязательно один запрос на хабы поля (weekly roundup, news tracker, community news); во второй проход — только имена из результатов или сообщения пользователя, не догадки; правило 9 «держаться темы, как её понимает пользователь»: явно постороннее не включать, спорное — в конец с пояснением (пример «слух о релизе ≠ порт» убран: для пользователя будущая ПК-версия GTA 6 как раз в теме; личный порядок важности — в «Памяти» Open WebUI, не в навыке); в ответах-продолжениях тоже ссылки. То же — в подсказке инструмента после первого прохода.

### Шестая итерация: навык поиска — только метод

Попытка положить критерии важности пользователя в навык (общий порядок плюс разобранный пример про эмуляцию) отменена: навык поиска подключается к любой теме, предметный пример ехал бы в каждый поиск, устаревал бы и смещал ответы по другим темам; «Память» тоже не подходит (включён фоновый пересмотр памяти, модель сама переписывает записи). Решение пользователя: что важно, он пишет сам в запросе. Правило 8: «если пользователь в сообщении сказал, что важно и в каком порядке, — ровно так; иначе передний край и громкие имена, затем крупные релизы известного, затем остальное, мелочь строкой "Ещё: …"». Правило 9: специальный смысл слов пользователя, смежное — в самый конец.

## Проверка формул (план размышлений, шаг 4)

Сравнение двух ответов на один вопрос по физике (спиновые структуры на торе): ядро одинаковое и верное, но во втором ответе формула импульса k = 2π/L·(n + (1−ε)/2) при ε = −1 давала целый сдвиг, хотя через две строки модель сама писала «k ~ π/L». Формула была по памяти и не проверена своими же случаями. В шаг 4 добавлено: каждую формулу в ответе проверять подстановкой тех частных случаев, которые описаны в тексте (каждый знак, n = 0, пределы), размерностью и простым известным результатом; с execute_code — через sympy/numpy; не прошла — исправить или убрать. Проверка тем же вопросом: Gemma вывела формулу из e^{ikL} = ε, подставила ε = ±1 и дала верное k = π/L·(2n + (1−ε)/2). Цена — длинные рассуждения (≈11 тыс. символов и 96 с на однострочный ответ, проверки повторялись), правило «каждую проверку один раз» соблюдается не полностью.
