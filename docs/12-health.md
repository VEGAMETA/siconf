# Медицина: клинрекомендации, литература, инструкции

Для вопросов о здоровье пользователя и родных (2026-10-26). Пользователь — врач: Gemma отвечает как коллега, прямо и со ссылками на источники, без оговорок «я не врач».

## Источники и инструменты

- **База знаний «Клинические рекомендации Минздрава РФ»** (Open WebUI → Знания), подключена к модели `gemma-4-26b-a4b` (`meta.knowledge` в `owui_setup.py`). В контекст целиком не вставляется: модель видит название базы и ищет по ней встроенными инструментами (`query_knowledge_files` и т. п.).
  - `llm/health/clinrec_fetch.py` — выгрузка с cr.minzdrav.gov.ru через открытое API сайта: список — `POST https://apicr.minzdrav.gov.ru/api.ashx?op=GetJsonClinrecsFilterV2` (фильтр status, 777 действующих на 2026-10-26), текст по разделам — `GET …?op=GetClinrec2&id=<CodeVersion>` (заголовки Origin/Referer как у сайта). Разделы → Markdown; без списка литературы, состава рабочей группы и методологии (≈ четверть объёма). Стартовый набор — 92 распространённых состояния взрослых и детей (ключевые слова `KEYS` минус редкие `EXCLUDE`); отдельные рекомендации — по коду: `python -X utf8 clinrec_fetch.py 62_3 290_2`. Тексты (`D:\llm\health\clinrec\*.md`, 21 МБ) в репозиторий не кладутся.
  - `llm/health/upload_kb.py` — загрузка в базу (создаёт её по имени, пропускает уже загруженные). Эмбеддинги считает Open WebUI на процессоре: Open WebUI считает эмбеддинги дважды (коллекция файла и коллекция базы; обойти штатно нельзя: добавление в базу требует извлечённого текста, а его извлечение тоже запускает эмбеддинги) — 105–180 с на файл, весь набор ≈ 3,5–4,5 ч.
  - Модель эмбеддингов Open WebUI сменена с `sentence-transformers/all-MiniLM-L6-v2` (только английский) на **`BAAI/bge-m3`** (многоязычная, сильная на русском; на CPU — torch у Open WebUI без CUDA, видеокарту и Gemma не трогает). Старые эмбеддинги файлов из чатов сделаны прежней моделью — поиск по ним не работает, при необходимости переиндексировать.
- **Инструмент `llm/tools/medical_research.py`:**
  - `search_guidelines(query, age, code)` — **точный поиск по клинрекомендациям**, основной способ (с 2026-10-26). Индекс `D:\llm\health\clinrec.db` собирает `llm/health/clinrec_index.py` из тех же `clinrec\*.md`: 8,5 тыс. фрагментов по 0,7–1,8 тыс. символов внутри разделов и подразделов, SQLite FTS5 по основам слов (Snowball). Почему: база знаний на bge-m3 находит нужную КР, но факт внутри текста на 200–300 тыс. символов пропускает — на «целевой уровень мочевой кислоты» Gemma ответила «в материалах не указан», хотя в КР 936_1 он есть. Что сделано, чтобы поиск попадал:
    - сокращения раскрываются по «Списку сокращений» самой КР («продолжительность АБТ» находится по «антибактериальной терапии»), плюс короткий словарь синонимов запроса (длительность/продолжительность, антибиотик/антибактериальный, дозировка/доза);
    - в индексе название КР и возраст: `age="adults"`/`"children"` отделяет взрослую КР по пневмонии от детской;
    - сначала фрагменты из КР, в названии которой слова запроса («пневмония», «подагра»), потом остальные — иначе длинные таблицы чужих приложений перебивают по bm25; если все слова вместе не встретились — варианты без одного слова;
    - подразделы внутри «3. Лечение» записаны обычным текстом («3.1.1. Антибактериальная терапия») — распознаются и становятся разделами;
    - **к лучшему результату прикладывается весь его подраздел** (до 12 тыс. символов): Gemma не дочитывала сама и по одному фрагменту выбирала госпитальную схему для амбулаторного пациента.
  - `read_guideline(code, section)` — оглавление КР или подраздел целиком («3.1.1»).
  - Проверка: пневмония амбулаторно у взрослого без сопутствующих — было «бета-лактам + макролид, 7 дней» (схема для стационара), стало «амоксициллин 3 г/сут, макролиды не первой линией из-за резистентности, длительность по критериям достаточности, обычно 5–7 дней» (КР 654_2, 3.1.1); подагра — целевой уровень ≤ 360 мкмоль/л, при тяжёлых формах ≤ 300, старт аллопуринола 100 мг/сут.
  - Индекс пересобирать после `clinrec_fetch.py`: `D:\llm\law\.venv\Scripts\python.exe -X utf8 D:\llm\health\clinrec_index.py` (секунды). `snowballstemmer` — в окружении Open WebUI (uv pip), запасной путь — venv сборщика законов.
  - **Автоскачивание КР:** если в каталоге всех 777 действующих КР (`clinrec_catalog.json`, обновляется раз в месяц) есть рекомендация, совпадающая с запросом по названию и диагнозам МКБ лучше любой локальной, `search_guidelines` скачивает её (`clinrec_fetch.fetch`) и дописывает в индекс (`clinrec_index.add`) — секунда-две. «Ревматоидный артрит» скачал 250_3, хотя локально была КР по псориатическому артриту.
  - `search_medical_literature(query, study_type="any", years=0)` — **PubMed** (E-utilities, напрямую): ранжирование Best Match, 40 кандидатов → пересортировка по дизайну (мета-анализ, руководство, РКИ выше; письма и клинические случаи ниже; отозванные статьи выбрасываются), по цитируемости с поправкой на область (RCR из NIH iCite) и по совпадению слов запроса с заголовком; слабые журналы (Cureus и т. п.) понижаются. `study_type`: rct, meta, guideline, review; к выдаче с фильтром добавляется выдача без фильтра (крупные сравнительные когорты). По умолчанию без ограничения лет — классические РКИ доз 1980–2000-х. Из аннотации — результаты и выводы (с цифрами), у неструктурированных — начало и конец. Длинные запросы модели PubMed не находит (нужны все слова): формулировки статей («once daily» → «single daily dose»), без чисел и общих слов, варианты без одного слова (кроме первого — препарата), без фильтра по дизайну. Без ключа NCBI — 3 запроса в секунду: паузы и повторы (иначе вместо XML приходила ошибка лимита и молча включался Europe PMC). Europe PMC — только запасной.

Набор из 5 вопросов на узкой, но неоднозначной теме (дозы, кратность, длительность, выбор схемы одного препарата; КР и РКИ местами расходятся) плюс 2 контрольных на другие темы, чтобы не подгонять под одну. Скрипт и ответы — `D:\llm\eval\health` (локально, не в репозитории: тема личная). Оценки 0–5 по эталону из КР и найденных РКИ:

|---|---|---|
| v1 | исходный навык, поиск Europe PMC | 2,0 |
| v2 | навык: шаги по источникам | 1,6 |

Что выяснилось:

- **Навык сам по себе почти не работает.** Gemma читает правила и поступает по-своему (v2 хуже v1: приписала дозы FDA российской КР). Срабатывает то, что видно в выдаче инструмента: целый подраздел КР, подсказка «следующий шаг — РКИ», «это американские дозы, не КР».
- **Триггер навыка:** вопрос «<препарат> один или два раза в день» без других медицинских слов не включал навык (нет слов из списка) — ответ из памяти без единого вызова. Добавлены окончания действующих веществ в формах слова, мг, «раз в день» рядом с «пить/принимать», ТТГ/Т4.
- **Вопрос о лечении нужно явно назвать «сравнением»:** «не много ли», «сколько лучше», «сколько лечиться» модель закрывала диапазоном из КР, не доходя до исследований.
- **Главный ограничитель — слова поиска:** модель пишет «once daily vs twice daily», статьи — «single daily dose»; на «блокируй-замещай vs монотерапия» Cochrane не находится. Отсюда ослабление запроса в инструменте.
- **Ссылки не выдуманы:** все 12 PMID финального прогона настоящие и по теме.
- Остаётся: модель иногда называет когорту мета-анализом, не всегда делает вывод «доза в пределах КР, но по РКИ хватает меньшей»; редкий сбой генерации (символы `\u00b5` и случайная корейская буква в ответе на температуре 1.0).
- Против подгонки: в навыке и описаниях функций примеры с других тем (аллопуринол, метформин, варфарин); проверено поиском, что темы калибровки в них нет.

### search_evidence (после калибровки v6)

Главный ограничитель v1–v6 — слова запроса, которые писала модель. Новая функция `search_evidence(intervention, condition, aspect, comparator)`: модель описывает вопрос, запрос строит инструмент.

- Названия → рубрики MeSH через автоматическое сопоставление PubMed (поиск по базе MeSH ошибался: metformin → phenformin, gout → gout suppressants); рубрика принимается, только если совпадает с написанным хоть одним словом. Слова сверх рубрики обязательны фразой («metformin extended release»), иначе пропадает различие форм.
- Аспект (`dose`, `frequency`, `duration`, `regimen`, `safety`, `efficacy`, с синонимами) → подрубрика MeSH как главная тема статьи (`/administration and dosage[majr]`, `/adverse effects[majr]`) или слова аспекта в заголовке; с `[mh]` подрубрика стоит и там, где препарат лишь фон.
- Выдача по уровням: руководства → мета-анализы и обзоры → РКИ → крупные сравнительные и наблюдательные; по 2–4 лучших (позиция Best Match, RCR, аспект и препарат в заголовке), дубли версий обзора склеиваются. Для обзоров и руководств — добавочный поиск по фармакологической группе вещества (`[pa]`, группа из MeSH RDF id.nlm.nih.gov): обзоры часто о классе препаратов — так находится Cochrane.
- Карточка: дизайн из разметки PubMed (модель больше не называет когорту мета-анализом), n, предложения результатов с числами и вывод.
- `read_guideline` по главе отдаёт и все её подразделы (по одной вводной части модель решала, что доз в КР нет).

| Прогон | Q1–Q5 | Контроль Q6/Q7 |
|---|---|---|
| v6 (свободный запрос) | 3,4 | 4 / 4 |
| v7 (search_evidence) | 2,9 | 4,5 / 4,5 |
| v8 (синонимы аспектов, глава КР целиком) | 2,9 | 4,5 / 4,5 |

Поиск находит нужное стабильно (Cochrane, РКИ доз и кратности, крупные когорты по безопасности; все PMID настоящие), но оценка одного вопроса скачет между прогонами на ±1: модель то выбирает не тот аспект, то путает препарат (торговое название приняла за другое вещество), то прикладывает исследование о схемах к вопросу о дозе. Один прогон на версию этот разброс не различает — для сравнения версий нужно 3 прогона.
  - `drug_label(drug, route, form)` — официальная инструкция FDA (openFDA) по международному непатентованному названию: показания, дозы, противопоказания, взаимодействия, побочные эффекты, беременность; выбирается однокомпонентная рецептурная инструкция (а не комбинация); `route` (oral, topical, ophthalmic…) и `form` (immediate или modified-release: ER/XR/SR, пролонгированные) уточняют форму, по умолчанию — обычная внутрь; в ответе перечислены остальные формы вещества, чтобы модель могла уточнить. **api.fda.gov из России отвечает 403** — запросы идут через прокси v2rayN `127.0.0.1:10808`. Оговорка в ответе: американская инструкция, в России ориентир — ГРЛС. **Запасная копия:** `llm/health/openfda_offline.py` скачивает выгрузку openFDA drug/label (14 частей, 1,8 ГБ zip, 263 тыс. инструкций; download.open.fda.gov открывается напрямую) и собирает `D:\llm\health\openfda_labels.db` — 15 693 уникальные инструкции (на вещество, тип, способ применения и форму выпуска — самая свежая, только нужные разделы), 115 МБ; архивы удаляются. 263 тыс. в выгрузке — в основном одинаковые инструкции дженериков разных производителей, переупаковщиков и старые версии. Первая сборка (ключ «вещество + тип») склеивала таблетки и гель диклофенака, обычный и пролонгированный метформин — у них разные дозы. Если api.fda.gov недоступен (прокси выключен или заблокирован, 403/5xx, таймаут), `drug_label` берёт инструкцию из копии и пишет дату выгрузки. Обновлять запуском скрипта раз в несколько месяцев.

## Почему не graphify и не дообучение

- graphify — навык Claude Code (граф для вопросов ко мне), Gemma в Open WebUI им не пользуется. Графовый RAG помог бы вопросам через несколько звеньев (сочетание болезней и лекарств), но для «что говорят клинрекомендации о X» достаточно точного поиска по фрагментам.
- MedGemma (Google, 1.5 — 4B, январь 2026; 27B) построена на Gemma 3, версии на Gemma 4 нет; заняла бы видеокарту вместо основной модели и слабее в общих вопросах.

### Торговые названия → МНН (ГРЛС)

Модель путала торговые названия по памяти (в одном прогоне приняла торговое название антитиреоидного препарата за другое вещество и ответила о нём). Инструментом это не лечится — модель то вызывает его, то нет, — поэтому справку дописывает фильтр.

- `llm/health/grls_build.py` — весь Государственный реестр лекарственных средств (grls.rosminzdrav.ru, «Загрузите ГРЛС одним файлом»: ZIP ≈ 18 МБ, xlsx по статусам; ссылка `GetGRLS.ashx?FileGUID=…` меняется — берётся со страницы) → `D:\llm\health\grls.db`: 15,5 тыс. названий с МНН, фармгруппой, действует ли регистрация (исключённые и истёкшие тоже — старые бренды по-прежнему называют). Одно МНН разными написаниями склеивается. Venv — `D:\llm\law\.venv` (+ openpyxl).
- Фильтр `task_skills_auto` 0.4 находит названия в сообщении (с падежами, многословные: «Глюкофаж Лонг», «Аспирин Кардио») и дописывает «[Справка ГРЛС: Конкор® — МНН: Бисопролол (…). Ищи и отвечай по МНН.]», плюс включает навык health.
- Ложные срабатывания: названия-обычные слова отсеяны по словарю текстов кодексов (law.db, ≥ 3 употреблений); сравнение по основе, но слово сообщения должно совпадать с названием целиком кроме последней буквы; слова из 1–2 букв не обрезаются. Ошибки, найденные проверкой: «Конкор и …» распознавался как «Конкор АМ» (бисопролол + амлодипин) — короткое «АМ» обрезалось до пустой строки; «в корне» — как «Корнам». На 42 тыс. сообщений пользователя из сессий Claude Code после исправлений — ни одного ложного срабатывания.
- Рубрика MeSH принимается, если PubMed сопоставил её всему написанному (синоним: paracetamol → acetaminophen) или есть общее слово; проверка только на общее слово отбрасывала синонимы, и поиск шёл по слову, которого в статьях нет.

### Смежные аспекты и проверка по источникам

- `search_evidence` ищет заданный аспект и смежные (доза ↔ безопасность, длительность ↔ эффективность, схема ↔ безопасность и эффективность): модель часто выбирает соседний аспект. Смежным — одно место на уровне: в общей выдаче огромные исследования безопасности (FAST, CARES) вытесняли РКИ дозы за счёт цитирований.
- Фильтр `llm/functions/claim_check.py` (после ответа, priority −1 — раньше строки расхода): утверждения с цифрами или ссылкой на исследование → свой источник из выдачи инструментов этого ответа (сначала PMID, код КР, журнал и год, потом общие числа; из длинного подраздела КР — окно вокруг нужного места) → отдельный вызов Gemma без размышлений сверяет каждое утверждение только с его источником (Chain-of-Verification: проверяющий не видит ответа и не повторяет ошибку) → расхождения дописываются под ответом, ответ не меняется. 3–10 с. На прошлых ответах поймала: «у схемы А побочек меньше (Cochrane)» — в источнике больше, 16 % против 9 %; дозы FDA, приписанные КР; неверное n. Ложных тревог на хороших ответах не было. Чего не ловит: верные цитаты о другом препарате (это — справка ГРЛС).
- Источники идей: PICOs-RAG (arXiv 2510.23998) — запрос по PICO; MedTrust-RAG (2510.14400), VeriCite — проверка утверждений по источникам; Chain-of-Verification (2309.11495).
- Скрипт калибровки ждёт фильтров после флага done (блок проверки дописывается на несколько секунд позже).
